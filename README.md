# Anchor Logistic

Консольное приложение на C++ для учёта заказов логистической компании. Данные хранятся в SQLite, статусы заказов меняются в реальном времени: фоновый поток двигает их вперёд, а консоль показывает изменения. Клиент вводит обычный адрес, программа сама переводит его в координаты и строит маршрут.

## Цель проекта

Разработать консольное приложение, которое позволяет:

- регистрировать клиентов по адресу (адрес автоматически переводится в координаты);
- создавать заказы на доставку;
- выбирать транспорт в зависимости от веса груза;
- автоматически назначать свободного курьера;
- рассчитывать расстояние и примерное время доставки;
- сохранять данные в SQLite;
- симулировать прохождение заказа по этапам доставки;
- отображать актуальное состояние заказов в консоли.

## Сценарий работы

Главное меню:

```
1. Создать заказ
2. Текущее состояние заказов
0. Выход
```

В пунктах 1 и 2 сначала запрашивается ID клиента.

**Если клиент новый (первый заказ):**

1. Программа просит имя, телефон и адрес.
2. Адрес переводится в координаты через Nominatim. Если адрес не найден, пользователю предлагается уточнить его.
3. Клиент сохраняется в базе, ему выдаётся ID (его нужно запомнить), после чего работа продолжается.

**Если клиент уже есть:** ID проверяется по базе, при ошибке запрашивается повторный ввод.

**Создать заказ:** ввод веса груза, затем автоматический выбор транспорта, назначение свободного курьера и расчёт маршрута от склада до клиента.

**Текущее состояние заказов:** таблица заказов клиента, которая обновляется через заданный интервал, а изменения статусов выводятся в консоль.

## Планируемая функциональность

### Клиенты

- Регистрация нового клиента с выдачей ID.
- Хранение имени, телефона, адреса и координат клиента.
- Координаты определяются один раз при регистрации и дальше берутся из базы.
- Проверка существования клиента по ID.

### Курьеры и транспорт

- Типы транспорта: легковой автомобиль, грузовик, самолёт.
- Транспорт и курьеры создаются автоматически при первом запуске (стартовые данные).
- Хранение статуса занятости курьера.
- Проверка грузоподъёмности транспорта.
- Освобождение курьера после доставки заказа.

### Заказы

- Создание заказа с указанием клиента и веса груза.
- Автоматический выбор подходящего транспорта по весу.
- Автоматическое назначение свободного курьера.
- Расчёт маршрута от склада до клиента.
- Сохранение расстояния и времени доставки.
- Отмена заказа до начала доставки.

### Симуляция доставки

Статусы заказа:

```
Создан → Назначен → В пути → Доставлен
```

Симулятор работает в отдельном потоке и изменяет статус заказа через заданные интервалы времени. Скорость симуляции зависит от типа транспорта и времени, рассчитанного OSRM.

## Архитектура

```
ConsoleUI
    ↓
LogisticsService
    ├── Database
    ├── GeocodingService
    ├── RoutingService
    └── SimulationEngine
```

| Компонент          | Назначение                                                      |
| ------------------ | --------------------------------------------------------------- |
| `ConsoleUI`        | Меню, пользовательский ввод, таблицы и сообщения                |
| `LogisticsService` | Бизнес-правила: регистрация клиентов, создание заказов, назначение курьеров |
| `Database`         | Все SQL-запросы и работа с SQLite                               |
| `GeocodingService` | Перевод адреса в координаты через Nominatim                     |
| `RoutingService`   | Работа с `libosrm`, расчёт маршрута и времени                   |
| `SimulationEngine` | Фоновое изменение статусов заказов                              |
| `models`           | Структуры клиентов, заказов, курьеров и транспорта              |

Основной принцип: SQL-запросы находятся только в `Database`, вызовы OSRM — только в `RoutingService`, HTTP-запросы к Nominatim — только в `GeocodingService`. Пользовательский интерфейс не обращается напрямую к базе данных, OSRM или геокодеру.

Геокодер и маршрутизатор скрываются за интерфейсами (`IGeocoder`, `IRouteProvider`), чтобы сервисную логику можно было тестировать на заглушках и при необходимости заменить реализацию (например, на офлайн-геокодер).

## Планируемая база данных

| Таблица    | Основные поля                                                               |
| ---------- | --------------------------------------------------------------------------- |
| `clients`  | `id`, `name`, `phone`, `address`, `longitude`, `latitude`                   |
| `vehicles` | `id`, `type`, `capacity_kg`, `speed_kmh`, `is_available`                    |
| `couriers` | `id`, `name`, `vehicle_id`, `is_available`                                  |
| `orders`   | `id`, `client_id`, `courier_id`, `weight_kg`, `status`, `created_at`        |
| `routes`   | `id`, `order_id`, `distance_meters`, `duration_seconds`                     |

`id` клиента выдаёт сама база (`INTEGER PRIMARY KEY AUTOINCREMENT`). SQLite используется как единый локальный файл. Для предотвращения конфликтов при работе симулятора доступ к базе синхронизируется с помощью `std::mutex` или отдельных соединений SQLite для разных потоков.

## Геокодирование (Nominatim)

Адрес клиента переводится в координаты запросом к Nominatim:

```
GET https://nominatim.openstreetmap.org/search?q=<адрес>&format=json&limit=1&countrycodes=by
```

Правила:

- запрос выполняется один раз при регистрации клиента, координаты сохраняются в `clients`;
- не чаще одного запроса в секунду;
- в каждом запросе указывается собственный `User-Agent`;
- адрес в запросе кодируется (url-encode);
- Nominatim возвращает `lat` и `lon` строками и в порядке `lat, lon`, а OSRM ждёт `lon, lat`, поэтому порядок меняется при сохранении;
- если адрес не найден, пользователю предлагается ввести его заново.

Для работы геокодирования нужно подключение к интернету.

## Интеграция OSRM

Для маршрутов используются подготовленные данные OpenStreetMap (Беларусь, Geofabrik) в формате OSRM.

```
C++ приложение
    ↓
RoutingService
    ↓
libosrm
    ↓
локальные данные дорожной сети OpenStreetMap
```

Планируемые возможности OSRM:

- `Route` — маршрут между складом и клиентом;
- расстояние в метрах;
- длительность в секундах;
- обработка ошибок при отсутствии маршрута;
- `Table` — матрица расстояний между несколькими точками после завершения первой версии.

OSRM использует координаты в порядке:

```
longitude, latitude
```

Поэтому координаты клиентов и склада хранятся в этом формате.
