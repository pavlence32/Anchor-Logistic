# Anchor Logistic

Консольное приложение на C++ для учёта заказов логистической компании. Данные хранятся в SQLite, статусы заказов меняются в реальном времени: фоновый поток двигает их вперёд, а консоль показывает изменения.

## Цель проекта

Разработать консольное приложение, которое позволяет:

- добавлять клиентов, курьеров и транспорт;
- создавать заказы на доставку;
- выбирать транспорт в зависимости от веса груза;
- автоматически назначать свободного курьера;
- рассчитывать расстояние и примерное время доставки;
- сохранять данные в SQLite;
- симулировать прохождение заказа по этапам доставки;
- отображать актуальный список заказов в консоли.

## Технологии

| Технология | Назначение |
|---|---|
| C++17 / C++20 | Основной язык разработки |
| CMake | Сборка проекта |
| SQLite3 | Хранение данных в локальной базе |
| libosrm | Расчёт маршрутов доставки |
| OpenStreetMap | Дорожные данные для OSRM |
| `std::thread` | Фоновая симуляция доставки |
| `std::mutex` | Защита общих данных между потоками |
| Git / GitHub | Контроль версий и совместная разработка |
| GoogleTest или Catch2 | Модульное тестирование |

Для маршрутизации планируется использовать `libosrm` — C++-библиотеку OSRM. Она позволяет встроить расчёт маршрутов напрямую в приложение, без отдельного HTTP-сервера: приложение создаёт объект `OSRM` через `EngineConfig`, передаёт параметры маршрута и получает расстояние и длительность пути. ## Планируемая функциональность

### Клиенты

- Добавление, просмотр и поиск клиентов.
- Хранение имени, телефона и координат клиента.
- Использование координат клиента для расчёта маршрута доставки.

### Курьеры и транспорт

- Добавление курьеров.
- Назначение транспорта курьеру.
- Хранение статуса занятости курьера.
- Проверка грузоподъёмности транспорта.
- Освобождение курьера после доставки заказа.

### Заказы

- Создание заказа с указанием клиента и веса груза.
- Автоматический выбор подходящего транспорта.
- Автоматическое назначение свободного курьера.
- Расчёт маршрута от склада до клиента.
- Сохранение расстояния и времени доставки.
- Поиск заказа по идентификатору.
- Отмена заказа до начала доставки.

### Симуляция доставки

Статусы заказа:

```text
Создан → Назначен → В пути → Доставлен
```

Симулятор работает в отдельном потоке и изменяет статус заказа через заданные интервалы времени. Скорость симуляции может зависеть от типа транспорта и времени, рассчитанного OSRM.

### Консольный интерфейс

Планируемые команды:

```text
1. Добавить клиента
2. Добавить транспорт
3. Добавить курьера
4. Создать заказ
5. Показать список заказов
6. Найти заказ по ID
7. Показать маршрут заказа
8. Запустить режим live
0. Выход
```

В режиме `live` таблица заказов обновляется через определённый интервал, а изменения статусов выводятся в консоль.

## Архитектура

```text
ConsoleUI
    ↓
LogisticsService
    ├── Database
    ├── RoutingService
    └── SimulationEngine
```

| Компонент | Назначение |
|---|---|
| `ConsoleUI` | Меню, пользовательский ввод, таблицы и сообщения |
| `LogisticsService` | Основные бизнес-правила: создание заказов и назначение курьеров |
| `Database` | Все SQL-запросы и работа с SQLite |
| `RoutingService` | Работа с `libosrm`, расчёт маршрута и времени |
| `SimulationEngine` | Фоновое изменение статусов заказов |
| `models` | Структуры клиентов, заказов, курьеров и транспорта |

Основной принцип: SQL-запросы находятся только в `Database`, вызовы OSRM — только в `RoutingService`, а пользовательский интерфейс не обращается напрямую к базе данных или библиотеке маршрутизации.

## Планируемая база данных

| Таблица | Основные поля |
|---|---|
| `clients` | `id`, `name`, `phone`, `latitude`, `longitude` |
| `vehicles` | `id`, `type`, `capacity_kg`, `speed_kmh`, `is_available` |
| `couriers` | `id`, `name`, `vehicle_id`, `is_available` |
| `orders` | `id`, `client_id`, `courier_id`, `weight_kg`, `status`, `created_at` |
| `routes` | `id`, `order_id`, `distance_meters`, `duration_seconds` |

SQLite будет использоваться как единый локальный файл базы данных. Для предотвращения конфликтов при работе симулятора доступ к базе должен быть синхронизирован с помощью `std::mutex` или отдельных соединений SQLite для разных потоков.

## Интеграция OSRM

Для маршрутов будут использоваться подготовленные данные OpenStreetMap в формате OSRM.

```text
C++ приложение
    ↓
RoutingService
    ↓
libosrm
    ↓
локальные данные дорожной сети OpenStreetMap
```

Планируемые возможности OSRM:

- `Route` — маршрут между складом и клиентом;
- расстояние в метрах;
- длительность в секундах;
- обработка ошибок при отсутствии маршрута;
- `Table` — матрица расстояний между несколькими точками после завершения первой версии.

OSRM использует координаты в порядке:

```text
longitude, latitude
```

Поэтому координаты клиентов и склада будут храниться в этом формате.
