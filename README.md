# Логистическая компания: консольное приложение

Консольное приложение на C++ для учёта заказов логистической компании. Данные хранятся в SQLite, статусы заказов меняются в реальном времени: фоновый поток двигает их вперёд, а консоль показывает изменения.

## Возможности

- Создание заказов, клиентов и курьеров
- Автоматический выбор транспорта по весу груза
- Автоназначение свободного курьера с подходящим транспортом на новый заказ
- Автоматическая смена статусов заказов в фоновом потоке
- Освобождение курьера после доставки
- Режим «live»: таблица заказов обновляется раз в секунду, события смены статуса выводятся сразу
- Поиск заказа по id
- Загрузка тестовых данных из файла
- Хранение данных в SQLite (один файл)

## Статусы заказа

```
Создан → Назначен курьер → В пути → Доставлен
```

## Транспорт

Вид транспорта выбирается автоматически в зависимости от веса груза:

- легковой автомобиль
- грузовик
- самолёт

Пороги веса задаются константами в одном месте: `config.h`. Курьеру назначается заказ только с тем видом транспорта, на котором он работает. Скорость смены статусов зависит от транспорта.

## База данных

SQLite, подключается к C++ как библиотека `sqlite3`. Все SQL-запросы находятся только в классе `Database`, остальные модули вызывают его методы.

| Таблица    | Поля                                                  |
|------------|-------------------------------------------------------|
| `orders`   | id, откуда, куда, вес груза, транспорт, статус, время |
| `couriers` | id, имя, транспорт, занят/свободен                    |
| `clients`  | id, имя, телефон                                      |

## Архитектура и распределение задач

Команда из 3 человек. Сначала согласуются заголовочные файлы (`models.h`, `events.h`, `database.h`, `logistics_service.h`, `ui.h`), затем реализации пишутся параллельно.

### Участник 1: данные и сборка (Brodiga585)

- Класс `Database`: подключение, создание таблиц
- CRUD-методы: добавить, получить, обновить статус, удалить заказ, курьера, клиента
- `models.h` и `config.h`: структуры данных и константы
- Метод `find_free_courier(Transport)`: поиск свободного курьера с нужным транспортом
- Метод `set_courier_busy(id, bool)`: занять или освободить курьера
- Потокобезопасность БД: `std::mutex` внутри `Database` или отдельное соединение на поток
- `CMakeLists.txt`, подключение `sqlite3`
- Тесты `Database`

### Участник 2: логика и «реальное время» (pavlence32)

- `enum class Transport` и выбор транспорта по весу груза
- Класс `LogisticsService`: создание заказа, назначение курьера (через `find_free_courier`), освобождение курьера при доставке
- Класс `Simulator`: поток на `std::thread`, раз в N секунд двигает статусы вперёд, скорость зависит от транспорта, корректная остановка потока
- Защита общих данных через `std::mutex`
- Механизм событий: сервис вызывает callback при смене статуса
- Тесты сервиса

### Участник 3: интерфейс и интеграция (I-Anufryieu)

- Главное меню: создать заказ (с вводом веса), список заказов, поиск по id, добавить курьера, выход
- Режим «live»: перерисовка таблицы раз в секунду, подписка на события из `events.h`, вывод событий смены статуса
- Отображение транспорта в таблице заказов
- Валидация ввода, форматирование таблиц
- Загрузка тестовых данных из файла
- `main.cpp`, сквозное тестирование, README

## Что согласовать в первый день

1. Поля всех структур в `models.h`.
2. Тип события и callback в `events.h`, например `using StatusCallback = std::function<void(const StatusEvent&)>;`.
3. Сигнатуры `Database`, `LogisticsService` и `Ui` в заголовках.
4. Кто освобождает курьера: сервис, через `Database::set_courier_busy(id, false)`.
